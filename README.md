# Парсер описаний товаров: яблоки

Скрипт разбирает свободные текстовые описания товаров (`descr`) и выделяет из них структурированные признаки:
**сорт, цвет, тип фасовки и вес**. Результат сохраняется в Excel, подозрительные случаи пишутся в лог.

## Быстрый старт

**Требования:** Python 3.12+ (в `filesHandler.py` в f-строке используются вложенные кавычки того же вида), `pandas`, `openpyxl`.

```bash
pip install pandas openpyxl
python main.py
```

**Входные данные** (пути заданы в `filesHandler.py`):

| Файл | Содержимое |
|---|---|
| `data/data/raw_desc.csv` | колонки `prod_id`, `descr` |
| `data/data/apple_var.xlsx` | справочник сортов: `name_var` (написание/алиас, в нижнем регистре) → `name` (каноническое название) |

**Выходные данные:**

- `result_<гг-мм-дд_чч-мм-сс>.xlsx` — исходные колонки + 5 новых признаков (в текущей папке); ненайденные значения — пустые ячейки;
- `logs/parser_<гг-мм-дд>.log` — предупреждения о подозрительном весе и факт сохранения результата.

## Логика выделения признаков

Для каждой строки `decomposeDecription(descr, aliases)` приводит текст к нижнему регистру и независимо применяет пять правил. Если правило ничего не нашло, возвращается `None` (в Excel — пустая ячейка).

| Колонка | Функция | Возможные значения |
|---|---|---|
| `apple_variety` | `findAliases` | название сорта из справочника или `None` |
| `apple_keyword` | `confirmIsApple` | `Яблоки` или `None` |
| `apple_color` | `checkColor` | `Красный` / `Зеленый` / `Желтый` / `None` |
| `apple_package` | `checkPackageType` | `Весовое` / `Фасованное` / `None` |
| `apple_weight_KG` | `figureWeight` | число в кг или `None` |

### Сорт (`findAliases`)

Перебирает ключи справочника в порядке их следования и возвращает значение для **первого** ключа, найденного в тексте как отдельное слово (`\bключ\b`). Если совпадений нет, возвращается `None`.

### Признак «это яблоки» (`confirmIsApple`)

Ищет начало слова `яблок` (`\bяблок`). Совпало — `Яблоки`, иначе `None`. Признак служит только пометкой: остальные правила применяются к строке независимо от него.

### Цвет (`checkColor`)

1. Текст приводится к нижнему регистру, `ё` заменяется на `е`.
2. Из текста вырезаются «ложные друзья» — слова, начинающиеся с `краснодар`, `краснояр`, `краснод` (регион, а не цвет).
3. Ищутся основы `зелен`, `красн`, `желт` в начале слова; выбирается тот цвет, который встречается **раньше всех** в тексте.

### Тип фасовки (`checkPackageType`)

Ищутся основы `вес` и `фас` в начале слова. Берётся первая основа в порядке словаря (`вес`, затем `фас`), а не по позиции в тексте. Нет совпадений — `None`.

### Вес (`figureWeight`)

1. Регулярное выражение `число + единица` (`кг`, `килограмм`, `kg`, `г`, `гр`, `грамм`, `g`). Число может быть с запятой или точкой; перед ним не должно стоять цифры. После единицы не должно идти буквы.
2. Берётся **первое** найденное совпадение и переводится в килограммы.
3. Если числа нет, но есть отдельное слово `кг` / `килограмм` / `kg` (например, «яблоки вес кг»), вес принимается равным `1.0`.
4. Иначе — `None`.

Проверки на подозрительные значения (пишется предупреждение в лог, значение остаётся в результате):

- число из последних 3 лет с единицей `г` («урожай 2024г») — похоже на год;
- вес больше 50 кг — слишком большое значение.

## Что уже исправлено

- **Единое значение для пропусков.** Вместо строк `"NaN"` / `"Nan"` теперь возвращается `None`, в Excel это пустые ячейки. Раньше `"NaN"` при чтении в `pandas` превращался в пропуск, а `"Nan"` оставался текстом.
- **Опечатка в названии колонки.** `apple_wtight_KG` → `apple_weight_KG`.

## Известные проблемы и способы решения

Приоритет: 🔴 влияет на корректность данных, 🟠 заметно снижает полноту, 🟡 качество кода и удобство.

### Определение сорта

| # | Проблема | Примеры из данных | Решение |
|---|---|---|---|
| 1 🔴 | **Результат зависит от порядка строк справочника, а не от текста.** Берётся первый подошедший алиас, а не самый длинный или самый ранний. Короткий общий алиас «перебивает» точный | Сорт `ред` присвоен 144 строкам, среди них 91 «Ред Чиф» и 45 «Ред Делишес» (при этом результат `ред чиф` встречается всего 2 раза). Аналогично `пинк` (59) для «Пинк Леди», `гала` (50) для «Роял Гала» | Сортировать ключи по длине по убыванию (так уже сделано для единиц веса); либо искать все совпадения и выбирать самое длинное. Решить с владельцем справочника, должен ли «Ред Чиф» быть отдельным сортом |
| 2 🟠 | **Несколько сортов в одной строке** — возвращается только один | `Ред Чиф/Ред Делишес`, `ДЖОНАГОЛЬД / ДЖОНАГОРЕД`, `яблоки россия 65 ассорти (голден, симиренко, грени смит)` | Возвращать список всех найденных сортов (через разделитель) или помечать строку признаком «микс» |
| 3 🟠 | **Опечатки и варианты написания, которых нет в справочнике.** Многие варианты справочник уже покрывает (`гольден`, `грани смит`, `семеренко`, `идаред`, `криппс` и др.), но остаются непокрытые | `фу-ши` (3 строки), `семиринка`, `айдоред`, `найдаред`, `бребурн` (по 1) | (а) Дополнить `apple_var.xlsx`; (б) нормализовать текст (`-` → пробел, `э` → `е`, `рэд` → `ред`); (в) нечёткое сравнение (`rapidfuzz`, порог ≈ 85–90) для слов, похожих на алиасы; (г) логировать слова после «яблоки», не найденные в справочнике, и регулярно пополнять справочник |
| 4 🟡 | **Разные принципы выбора совпадения.** Цвет выбирается по ближайшему к началу тексту, сорт и фасовка — по порядку словаря | — | Привести все три функции к одному правилу: «по позиции в тексте с приоритетом более длинного совпадения» |
| 5 🟠 | **Признаки извлекаются у строк без слова «яблоки».** `apple_keyword` лишь помечает строку, остальные правила работают независимо от него. Кроме того, слово «яблоки» не гарантирует свежий фрукт | «Слива красная 3шт» получает цвет `Красный`; «яблоки протертые с сахаром 430г», «яблоки, слива, крыжовник, алыча в сиропе 880г» и «яблоки для сока» обрабатываются как свежие яблоки | Ввести булевый признак `is_fresh_apple`: слово «яблок» плюс **стоп-слова** (`сироп`, `протерт`, `пюре`, `сок`, `переработк`, `варень`, `слива`, …). Для не-яблок остальные признаки не извлекать |

### Цвет

| # | Проблема | Примеры из данных | Решение |
|---|---|---|---|
| 6 🟠 | **Цвет найден лишь в 6 % строк.** В большинстве описаний его нет, хотя он однозначно следует из сорта | «Голден» → жёлтый, «Гренни Смит» → зелёный, «Ред Чиф» → красный | Добавить в справочник сортов колонку `color` и заполнять цвет по сорту, если в тексте его нет. Хранить источник (`text` / `variety`), чтобы отличать найденное от выведенного |
| 7 🔴 | **Несколько цветов — сохраняется один** | `Яблоки зелено-красные` → `Зеленый`; `красно-желтые Айдаред` → `Красный`; `КРАСНЫЕ/ЗЕЛЕНЫЕ` | Возвращать список цветов или значение `Смешанный`; дефисные составные слова обрабатывать отдельно |
| 8 🟠 | **Слова, начинающиеся с основы цвета, но не являющиеся цветом** | Сорт «Красный Рим» → цвет `Красный`; слова вида `красногорск`, `зеленоград`; рекламное «красная цена» | Расширить `FALSE_FRIENDS_RE` и/или проверять, что основа цвета согласована со словом «яблок…» |
| 9 🟡 | **Бедный список цветов:** нет «розовый», «бордовый», «полосатый» | `розовые`, `бордовое`, `полосатые` | Расширить словарь `colors`, если такие значения нужны в аналитике |

### Тип фасовки

| # | Проблема | Примеры из данных | Решение |
|---|---|---|---|
| 10 🔴 | **Конфликт «вес» и «фас»** в одной строке — всегда побеждает «Весовое» из-за порядка в словаре | `Яблоки Роял Гала фас, вес`, `Яблоки Гольден фас ун вес CTM`, `ЯБЛОКИ РЕД ЧИФ ВЕС/ФАС` | Считать все найденные признаки; при конфликте возвращать `Неоднозначно` и писать предупреждение в лог. | 11 🔴 | **Ложные срабатывания основы `вес`** | `подложка ВЕСЕНИН фас кг` — «ВЕСЕНИН» это бренд, при этом строка получает `Весовое`; возможны «весенние», «весна» | Заменить `\bвес` на точные формы: `\bвес(?:ов\w*)?\b`; для `фас` — `\bфас(?:ов\w*)?\b` |

Помечать такие значения как «выведено», а не «найдено» |
